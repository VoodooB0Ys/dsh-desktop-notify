# 桌面提醒体验修复：原生横幅、全屏穿透、点击跳到最后一轮

## 背景

`dsh-desktop-notify` 目前"基本能用"，但细节没达到用户预期。用户提出的 5 条要求来自真实使用：
他在别的窗口 / 全屏看视频时被 agent 卡住进度，而提醒要么没弹、要么弹了却回不到该看的对话。

现状要点（详见 `research/runtime-findings.md`）：

- profile 实际加载的是 `%USERPROFILE%\.dsh\my-dsh\dsh-desktop-notify`，与工作区仓库是两份。
- 当前 live 配置是 `channels.toast=false / alert=true`：**只弹自绘置顶卡片，不发系统原生横幅**。
- `user-questions/request`、`approval/request` 两个 waterfall 订阅在 DSH 0.2.0-rc.2 上**实测收不到**
  （2026-09-26 之后一次都没到），所以「等你回答 / 等你授权」这类最关键的提醒是哑的。
- 点击提醒后，宿主确实收到了会话 id，但客户端最终只把 DSH 窗口抬到最前，没有切到那个对话。

## 目标（逐条对应 5 个要求）

- **R1 原生横幅**：提醒默认走 Windows 原生 Toast 横幅（进通知中心），而不是只弹自绘卡片。
- **R2 全屏也要弹**：用户在全屏看视频时，提醒仍然必须出现在屏幕上，不能只在通知中心躺一条。
- **R3 门控逻辑**：只有「用户当前没在看发出提醒的那个对话」时才提醒；正在看那个对话就不打扰。
  这条与现状一致，本次保持并补测试。
- **R4 等待类事件不漏报**：`ask_user_question`（含 grilling / trellis-brainstorm 的问卷、计划审阅）
  与「需要授权」都必须触发提醒，不能静默卡住进度。
- **R5 点击跳转**：点击横幅/卡片要真正切到对应对话，并定位到该对话的**最后一轮**（最新内容），
  而不是只把 DSH 窗口抬到最前。

## 非目标

- 不做 macOS / Linux 支持。
- 不做通知中心历史管理、分组、免打扰时段配置。
- 不重构客户端 UI，不改 DSH 本体。
- 不追求在**独占全屏游戏**（exclusive fullscreen）下 100% 显示原生横幅 —— 见约束。

## 约束与已知风险（先说清楚，不硬做）

- **原生横幅在独占全屏下会被 Windows 压掉且不补弹**，这是系统行为，插件无法绕过。
  因此 R2 用「原生横幅 + 前台是全屏时补一张我们自己的置顶卡片」来保证，卡片是兜底而不是主通道。
- **客户端只负责收/发消息**：如果 DSH 页面完全没开着，点击跳转无人接管，只能唤前窗口（保留现状）。
- **「定位到最后一轮」没有公开 API**：DSH 客户端没暴露滚动接口，只能走「切会话 + 尽力滚到底部」，
  属于 best-effort；若 DSH 内部结构变化可能失效，届时降级为「只切会话」并记日志。
- **改代码必须重启 Harness**：热重载只会重跑 `apply()`，ESM 缓存不失效（实测），所以验证需要重启一次宿主。
- 插件会优先使用「会话事件流」这条已被证实可达的通道；waterfall 订阅保留作为冗余，两者用去重合并，
  避免重启后若 waterfall 恢复导致重复提醒。

## 验收标准

- [ ] A1 默认配置下，一个回合正常结束时屏幕上出现的是 **Windows 原生 Toast 横幅**，通知中心里能查到该条。
- [ ] A2 前台是全屏应用（如全屏视频）时，同一次提醒仍然可见：要么原生横幅穿透，要么出现置顶卡片；
      两者不会同时出现两条。
- [ ] A3 用户正在看「发出提醒的那个对话」时，不弹、不响（日志留 `skip …: user is looking at this conversation`）。
- [ ] A4 触发 `ask_user_question` 时，处于「没在看该对话」状态的用户收到一条「需要你回答」提醒，
      且横幅正文能看出问的是什么（题干/选项摘要）。
- [ ] A5 触发一次工具授权请求时，收到一条「需要你授权」提醒，文案含工具名与原因。
- [ ] A6 点击提醒后 DSH 窗口被唤前 **且** 切到对应会话；若该会话不是最新状态，视图停在最新内容处。
- [ ] A7 一条提醒只会弹一次（同一事件、同一会话在去重窗口内不重复）。
- [ ] A8 `debug` 日志能完整复现每次判定：为什么弹 / 为什么不弹 / 点击后走了哪条跳转路径。
- [ ] A9 README 更新：三份副本与部署方式、新默认值、全屏兜底策略、已知限制。
